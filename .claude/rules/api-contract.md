# API contract

The HTTP contract between the backend and the SPA. Neighbours: `server-architecture.md` for routers,
`frontend.md` for the client's use. Facts: `docs/architecture.md` «Routes and API».

## Rules

- The OpenAPI schema generated by FastAPI from routers and `schemas.py` is the contract; the SPA client in
  `frontend/src/api/generated/` is generated from it and committed.
- A contract change in lockstep, in one change: schemas → routers → regenerate the client
  (the `just` recipe from task 0.1) → update the SPA → `docs/architecture.md` «Routes and API».
- Paths are versioned: `/api/v1/...`.
- Every route declares `response_model`, status codes and its error responses.
- Errors are structured JSON: `{"error": {"code": "<machine_code>", "message": "<Russian text>"}}`;
  codes are a closed set per module.
- An entity outside the caller's scope answers 404, not 403.
- Request bodies are pydantic models with `extra="forbid"` and size limits.

## Never

- Never hand-edit the generated client or add a hand-written duplicate endpoint call.
- Never change a response field's meaning without a new field or a new version.

Enforced by: the client regeneration check in `just check` (task 0.1), review.
